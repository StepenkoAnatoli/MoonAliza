# Discovery Contract - Can the MoonAliza Electron desktop app sign users in to GitHub (OAuth device flow or another desktop-suited flow), to Claude with a Claude.ai subscription account, and to OpenAI Codex with Sign in with ChatGPT, and use those sign-ins for repository access and model calls - or must third-party apps use API keys

## Build intent

MoonAliza (an Electron/TypeScript desktop coding agent, Windows first) wants a "sign in" button for three services, from the user's question "Can we make the app be able to login to GitHub/codex/Claude?": GitHub, so the agent can read and work on the user's repositories (private ones included); Claude, so the user's Claude.ai subscription (Free/Pro/Max) pays for model calls instead of an Anthropic API key; and OpenAI/Codex, so the user's ChatGPT plan pays for model calls the way Codex CLI's "Sign in with ChatGPT" does, instead of an OpenAI Platform API key. Done, for this corpus, means a builder can tell for each of the three, from owner pages: whether the provider allows a third-party desktop app to do it at all; if yes, which app registration, flow, scopes or permissions, token lifetimes and refresh, and rate limits the implementation must handle; if no, what the provider requires instead. A permission is never inferred from silence: where the owner does not say, the row says "not stated".
