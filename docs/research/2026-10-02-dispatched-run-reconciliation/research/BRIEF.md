## Intent

Durable reconciliation of GitHub Actions runs for MoonAliza's Stage E (research
provisioning and durable GitHub job reconciliation, HANDOFF.md). MoonAliza dispatches a
workflow with `workflow_dispatch`, may be closed or restarted before the run ends, and must
later find that exact run again, read whether it finished and how, and fetch its logs and
artifacts while they still exist. Done means a builder knows, from the owner's pages: how
the run's id is obtained at dispatch time or recovered afterwards, which endpoint reports
status and conclusion and in what values, how often it may be polled, and how long logs,
artifacts and the run record itself remain available.

## Decision

Build the reconciler as a record-first design, not a search-first one:

1. **At dispatch**, call `POST /repos/{owner}/{repo}/actions/workflows/{id}/dispatches`
   with `ref`, `inputs` and `return_run_details: true` (E-01, E-03), and persist the
   returned run id and URL in MoonAliza's durable job store before anything else happens.
   A 204 means the parameter was not honoured; then fall back to step 2 once, filtering
   `GET .../actions/runs` by `event=workflow_dispatch`, the dispatched `branch`, and a
   `created` window starting at the dispatch time (E-02), and persist the match.
2. **To reconcile**, poll `GET .../actions/runs/{run_id}` with a token holding Actions
   read (E-02); the job is finished when `status` is `completed`, and `conclusion` carries
   the outcome from the vocabulary in E-02. Keep polling well inside the token's primary
   limit - 5,000 requests per hour for a user token, 1,000 per repository for
   `GITHUB_TOKEN` (E-05) - and back off on a secondary-limit response.
3. **Fetch results before retention ends.** Logs, artifacts and, since 2026-10-01, the run
   record itself are deleted at the repository's retention period: 90 days by default,
   1-90 for a public repository, 1-400 for a private one (E-06, E-04). Treat a 404 on a
   run older than that period as "expired", not "never existed", and schedule the fetch
   of logs and artifacts as part of the job, not as a later convenience.

Out of scope: re-running or cancelling runs, GitHub App installation tokens (MoonAliza
uses a user token), and Enterprise Cloud limits.

First build step: add `return_run_details` to the existing dispatch call and persist the
run id it returns; write the test that asserts a dispatched job records a run id before the
first poll.
