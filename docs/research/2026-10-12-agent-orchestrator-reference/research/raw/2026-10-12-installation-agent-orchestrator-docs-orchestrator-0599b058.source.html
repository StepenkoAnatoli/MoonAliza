Installation

Download the Orchestrator desktop app and connect your coding tools.

For the latest stable desktop build, start at the official Orchestrator download page. It also lists nightly builds and the mobile apps. If you want a direct desktop package, choose one below:

On your phone, install Orchestrator Mobile for iPhone or iPad or Orchestrator Mobile for Android. Then use Connect Mobile in the desktop app to pair it.

The desktop app is the canonical install path. It owns the local daemon, requires no global ao command, and checks for updates after launch and while it is running.

Set up Orchestrator

Install and open the desktop app

Choose the download for your platform above, install it, and open Orchestrator. The app starts and supervises the local Go daemon automatically.

Authenticate GitHub

For a GitHub repository, install GitHub CLI if needed, then sign in:

Use an account that can read the repository and perform the branch and pull-request actions you expect the agent to take.

For GitLab, sign in with a GitLab token or glab. See source-control setup.

Install and sign in to an external agent

For an externally installed harness, install it and run it once outside Orchestrator to complete its sign-in flow. Orchestrator detects available harnesses when you create a session. If you use the built-in Unreal Agent, skip this step and choose it for a Chat session on supported macOS or Linux.

Chat support depends on the harness and installed version; see the agent capability catalog.

Add a project

In the desktop app, choose Add project and select an existing local Git repository. Orchestrator registers it without moving your original checkout. Each worker session gets its own isolated worktree.

You can also start a projectless standalone task for work that needs no repository. The optional CLI form is ao spawn --standalone --agent codex --name notes --prompt "Draft release notes"; standalone workers cannot claim a PR or take Git/project flags.

Legacy npm CLI

Already have the npm CLI?@aoagents/ao is frozen at 0.10.0 and is no longer recommended.

0.10.0 is the final npm release. The package remains a legacy bridge for existing users and will not receive new product features. Running ao start from that install fetches and opens the desktop build.

New users should install the desktop app directly instead.

Where Orchestrator stores data

All Orchestrator application state lives under ~/.ao by default, including the daemon database, run file, managed worktrees, Electron browser data, and mobile pairing configuration. Advanced installations can override daemon paths with AO_DATA_DIR and AO_RUN_FILE.

Common installation problems

No agent is available

For an external harness, install it, run it once to authenticate, then restart Orchestrator so the desktop-launched daemon receives the updated login-shell environment. Unreal Agent is built into Orchestrator for Chat on supported macOS and Linux; choose it directly instead of installing a CLI.

GitHub data is missing

Run gh auth status. Confirm the active account can access the repository and its pull requests.

Terminal UI cannot start on macOS or Linux

Packaged builds include tmux. New sessions normally use native PTY hosts; macOS still checks tmux availability and older sessions may need it. See runtime diagnostics for source installs and fallback behavior.

The legacy `ao` command is not found

The desktop app does not require it. Only troubleshoot the package manager's global bin path if you intentionally use the frozen legacy CLI.

macOS says the developer cannot be verified

In Finder, right-click Orchestrator, choose Open, then choose Open again in the confirmation dialog. If macOS still blocks the app, run these diagnostics and include the output when opening an issue:
