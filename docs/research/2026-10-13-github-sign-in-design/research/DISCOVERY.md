# Discovery Contract - What does a GitHub App device-flow sign-in in the MoonAliza Electron app need on GitHub's side to read a user's private repositories read-only, refresh and end its tokens, and stay within GitHub's limits?

Started 2026-10-13. This file is the definition of "enough information to build".
`node "/root/.agents/fetchproof/bin/preflight.mjs"` reads it and blocks the build until every unknown
below is either `CLOSED` with evidence or `KNOWN-UNKNOWN` with a verification step.

## Build intent

MoonAliza (an Electron + TypeScript desktop coding agent, Windows first) adds a "Sign in to GitHub" action so its `read_github` tool can read the user's private repositories, read-only. Today `read_github` (`src/main/github.ts`) reads public repositories only, with no credentials, through `GET /repos/{owner}/{repo}/commits/{ref}` and `GET /repos/{owner}/{repo}/contents/{path}` (header `X-GitHub-Api-Version: 2022-11-28`). The prior project `docs/research/2026-10-12-app-sign-in` (its `research/BRIEF.md`, gate PASS; in this branch since merge commit d0df7e9, and `../2026-10-12-app-sign-in` from this project's folder) already decided the shape: a GitHub App (not an OAuth app), the OAuth device flow (no client secret shipped in the binary), read-only repository contents, expiring user tokens kept in the app's encrypted safeStorage vault, and the user's shared 5,000 requests/hour. This project collects the design facts that brief left open. Done, for this corpus, means a builder can do each of these from owner pages in this project's own ledger, without guessing: register the app with the right settings (U-8) and permissions (U-1); run the device flow and handle every error it returns (U-3); tell which repositories the token reaches, list them, and send the user to install the app on more (U-2); explain a failed private read without claiming a cause it did not observe (U-10) and say who can install the app on an organization or another account (U-11); call only REST endpoints that accept the token for commits, contents, trees, blobs and archives (U-7) and show the signed-in login (U-15); refresh the token before it expires and know when a refresh has failed for good (U-4); end a sign-in, revoking the token if an app with no client secret can, and otherwise know what the user must do on GitHub, where (U-13), and when GitHub revokes tokens itself (U-5); validate the shape of GitHub's token responses (U-6); keep the REST API version knowingly (U-9); know the rate limits on the app's user tokens and device flow (U-12, U-16); and know how a later permission increase reaches users (U-14). Where an owner page does not say something, the row says "not stated"; nothing is inferred from silence, and an inference is labelled as one.
