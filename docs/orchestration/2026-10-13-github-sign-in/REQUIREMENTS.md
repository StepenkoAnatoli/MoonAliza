## Open fact (resolved)

- **OF-1: where the device-flow and refresh parameters go. Resolved in round 4 by E-21.**
  - E-01 l.118 and l.138, and E-02 l.72, call the inputs "query parameters". But E-01 l.122 and l.167 use the same words for response fields, so the reference pages do not say whether the inputs go in the URL or in a form-encoded body.
  - **Closed by GitHub's own tutorial** "Building a CLI with a GitHub App" (E-21, linked from E-01 l.112; 1 credit, approved by the lead, RUN.md). Both device-flow requests send their parameters form-encoded, with `Accept: application/json`, to URLs with no query string (E-21 l.300-304, l.315-322). That this is a form body is Ruby's standard library, an inference.
  - **The refresh** is not in E-21. It is sent the same way, which is an inference checked by DO-1, with DO-2 for reading a failure.
  - **Design decision (DR-9):** a form-encoded body with `Accept: application/json`, placed by one function, with no fallback.
