# Phase 2 day one: facts only a live Anthropic probe can confirm

Outcome (2026-10-12): the probes ran with the key under `MOONZILA_ANTHROPIC_API_KEY`; results in
`docs/evidence/2026-10-12-anthropic-probes.md`, summarised in the spec's "As built (Phase 2)". The rest of
this file is the plan as written before they ran.

The Anthropic parts of wire U-18 had not run: the probe session of 2026-10-11 found no Anthropic key in
its environment (RUN.md log), and the probes wait on the name of the variable the user saved the key
under. This build session sends no prompt to any vendor (Mandate stop-list). Phase 2 is built and merged
against fakes made from the captures (Mandate decision 7); nothing in the design depends on a probe's
outcome, and each row says what the code does until then.

**How every probe runs.** A probe session on the collector machine, with the user's key read from the
environment and never written anywhere; synthetic prompts only (no project content); a spend cap of
US$3 set before the run (the Phase 1 probe brief's figure; per-item estimates below); every raw request
and response line recorded, with any key material scanned out, in
`docs/evidence/<date>-anthropic-probes.md`. Measurements are evidence files, not corpus E-rows (the kit
admits fetched pages only). D10 needs no vendor: the transport builder (U2) runs it in Electron 44.4.5
under xvfb at the end of wave 1, before the U4 and U5 briefs are written, and the Windows e2e repeats
its header assertions (and, if commit 3 stays, its cookie assertions) on the exact head.

## Spend under the US$3 cap

Prices per million tokens, input / output, from the pricing corpus's E-01
(`docs/research/2026-10-02-model-pricing-and-ranking`, capture l.377-447; SL-E01 l.17 shows the same):
Fable 5.1 $10 / $50, Opus 5.5 $4 / $20, Sonnet 5.5 $2 / $10, Haiku 4.5 $1 / $5. Each bound below is a
worst case: every request generates its whole `max_tokens` (thinking included, E-13 l.48), or the
model's whole maximum output where the request asks for more; a small request carries at most 2,000
input tokens and a step-2 request at most 10,000 (signature size is not stated, D16). Whether a refused
request is billed is not stated, so D2 counts its input, and a request expected to be refused is costed
as if it were accepted (D7's over-maximum request): no item is costed at zero. "K" is read as 1,024
where it bounds a worst case (64K as 65,536 tokens, 128K as 131,072). Real spend should be far lower:
"Reply with OK." and a one-argument tool call do not use 4,096 tokens.
